Основной документ с прототипом: [`index.html`](./index.html) (§5)  
Интерактивный прототип: [`03_prototype_prompts_chain.html`](./03_prototype_prompts_chain.html)  
UI Kit: https://disk.yandex.ru/d/x5dlITdq4gUQMw

## Название
Объяснить цепочку «промпты → автоконкуренты / аналитика» на экране подобранных промптов перед «Создать проект»

## Целевой пользователь и проблема
**Пользователь:** PM / маркетолог нишевого B2B (персона — PM BEANABOX).  
**Проблема:** на шаге промптов не видно, что список задаёт автоконкурентов и основу аудита УТП → первая польза по отстройке приходит «кривой».

## Решение
**As-is:** как на экране создания проекта — info «Отредактируйте и добавьте свои промпты…», «Подобранные промпты» + «?», поле промптов, «Создать проект».  
**To-be (что меняется):** явная цепочка в alert; схема 4 шагов; расширенный «?»; warning + подпись у CTA.  
**Вне скоупа v1:** пресеты под видимость/репутацию/УТП; блокировка Create; ручные конкуренты на этом экране. См. прототип.

## Логика
Редактирование промптов без смены модели; Create при непустом списке; тексты статичны; post-Create flow без изменений.

## Границы v1
Входит: изменения из «Что меняется в to-be».  
Вне скоупа v1: пресеты под видимость/репутацию/УТП; блокировка Create; ручные конкуренты на этом экране; AI-перегенерация; смена алгоритма конкурентов; paywall/waiting.

## Проверка
Качество: пользователь называет связь с конкурентами/аудитом до Create (5–7 проходов сегмента).  
Количественные baseline не задаём — данных нет.

## Открытые вопросы
Точная зависимость автоконкурентов от промптов vs описания бренда; обещание аудита УТП в trial; нужен ли пример плохой/хороший промпт; тон warning-копирайта.
